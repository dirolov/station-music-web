# Station Music Web

Локальный веб-интерфейс для проигрывания музыки с компьютера на Яндекс Станции.

Приложение позволяет:

- выбирать отдельные аудиофайлы;
- добавлять папку целиком, с рекурсивным обходом или без него;
- открывать плейлисты `.m3u` и `.m3u8`;
- загружать файлы и целые папки через браузер;
- добавлять прямые HTTP/HTTPS-ссылки на аудиофайлы и радио-потоки;
- управлять очередью, текущим треком, стартом и остановкой воспроизведения;
- видеть и менять громкость Станции;
- читать метаданные и длительность треков;
- транскодировать аудио и передавать его колонке по HTTP.

Колонка не получает доступ к файловой системе компьютера. Приложение запускается на компьютере с музыкой, перекодирует выбранные треки в MP3 и отдаёт их Станции как HTTP-поток. На Станции воспроизведение запускается родным GStreamer-плеером `maind --gst-launch`.

## Как это работает

Проект опирается на идеи из `yandex-station-extended/contrib`:

- из `music.go` взята идея передачи колонке URL для воспроизведения;
- из `qstream.go` — идеи транскодирования, кэша и HTTP Range.

Эти файлы нельзя импортировать напрямую: они рассчитаны на окружение fake-Vins, protobuf-шаблоны, Navidrome и WebSocket-код. Поэтому нужная логика адаптирована в отдельное приложение.

Схема работы:

1. Пользователь выбирает файлы, папку, плейлист или вставляет прямую HTTP/HTTPS-ссылку в веб-интерфейсе.
2. Приложение проверяет пути и читает метаданные через `ffprobe`.
3. Аудио транскодируется через `ffmpeg` в MP3:
   - 44.1 кГц;
   - стерео;
   - CBR 192 кбит/с.
4. Каждый конечный трек отдаётся по отдельному HTTP-адресу с поддержкой HTTP Range. Следующий трек заранее перекодируется в кэш.
5. Прямые эфиры транскодируются в MP3 без записи на диск и передаются колонке сразу по мере получения данных.
6. Приложение подключается к Станции по ADB или SSH и запускает:

   ```sh
   cd /system/vendor/quasar
   LD_LIBRARY_PATH=/system/vendor/quasar:/system/vendor/quasar/libs
   ./maind --gst-launch \
     'souphttpsrc location=<stream-url> ! decodebin ! audioconvert ! audioresample ! alsasink'
   ```

7. После успешного завершения трека приложение запускает следующий трек очереди. При остановке или переключении завершает предыдущий процесс `maind --gst-launch`.
8. Приложение читает аппаратную громкость через `amixer get Master` и изменяет её штатным скриптом `/system/vendor/quasar/set_volume.sh`.

HTTP-ответ для каждого трека имеет фиксированный размер: `(duration + 1) × 24000` байт (192 кбит/с = 24000 байт/с). Остаток после MP3 заполняется тишиной. Текущий трек определяется по запущенному процессу, а переход происходит после его успешного завершения. Между треками возможна небольшая пауза.

Статус «Играет» появляется после двух проверок ALSA: устройство должно быть в состоянии `RUNNING`, а аппаратный указатель `hw_ptr` — увеличиваться. Один только запущенный процесс не подтверждает воспроизведение. Завершение и ошибки последнего запуска сохраняются в статусе до следующей команды управления.

## Требования

### На компьютере

- Go 1.22 или новее;
- `ffmpeg`;
- `ffprobe`;
- `adb` или `ssh`;
- каталог с музыкой;
- браузер.

Пример установки зависимостей в Debian/Ubuntu:

```sh
sudo apt update
sudo apt install ffmpeg adb
```

### На Яндекс Станции

- настроенный доступ по ADB (`IP:5555`) или SSH (`root@IP:2222`);
- сетевой доступ от колонки к компьютеру с приложением;
- рабочий `maind --gst-launch`.

Перед настройкой и каждым действием с колонкой сверяйтесь с локальной викой `yandex-station-extended/docs/`:

- оглавление: `yandex-station-extended/mkdocs.yml`;
- модель: `docs/devices/station-lite.md`;
- SSH: `docs/start/ssh.md`;
- сеть и порты: `docs/internals/network.md`.

## Быстрый старт

### 1. Подготовьте колонку

Для режима ADB подключитесь к ней с компьютера:

```sh
adb connect 192.168.1.7:5555
adb devices
```

В списке должно появиться устройство `192.168.1.7:5555`.

### 2. Разрешите доступ к веб-серверу

По умолчанию приложение слушает порт `8080`. Колонка должна иметь возможность подключаться к этому порту.

Если используется UFW и сеть доверенная, можно разрешить порт только внутри локальной сети, например:

```sh
sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp
```

Не открывайте порт `8080` в интернет.

### 3. Соберите приложение

```sh
cd station-music-web
go build -o stationmusic .
```

### 4. Запустите

Пример для ADB:

```sh
MUSIC_ROOT=/home/user/Music \
MUSIC_PUBLIC=http://192.168.1.9:8080 \
STATION_MODE=adb \
STATION_SERIAL=192.168.1.7:5555 \
./stationmusic
```

Откройте в браузере:

```text
http://192.168.1.9:8080/
```

Здесь:

- `192.168.1.9` — IP компьютера с музыкой;
- `192.168.1.7` — IP Станции.

Замените адреса на свои.

## Конфигурация

### Файл настроек

По умолчанию используется `station-music-web.json`. Можно указать другой файл:

```sh
./stationmusic -config /path/to/config.json
```

Пример:

```json
{
  "address": "0.0.0.0:8080",
  "musicRoot": "/home/user/Music",
  "cacheDir": "/home/user/Music/.station-music-cache",
  "uploadDir": "/home/user/Music/uploads",
  "publicBase": "http://192.168.1.9:8080",
  "stationMode": "adb",
  "stationSerial": "192.168.1.7:5555",
  "stationHost": "",
  "stationPort": 2222,
  "stationUser": "root"
}
```

### Основные поля

| Поле | Назначение |
|---|---|
| `address` | Адрес HTTP-сервера. Обычно `0.0.0.0:8080`, чтобы сервис был доступен в локальной сети. |
| `musicRoot` | Корень музыкальной библиотеки. Все выбираемые пути ограничены этим каталогом. |
| `cacheDir` | Каталог для перекодированных MP3. Можно удалять при остановленном приложении. |
| `uploadDir` | Каталог для файлов, загруженных через браузер. Всегда приводится внутрь `musicRoot`. |
| `publicBase` | Адрес, доступный колонке. Должен указывать на компьютер с приложением, а не на `127.0.0.1`. |
| `stationMode` | `adb` или `ssh`. |
| `stationSerial` | ADB-serial, например `192.168.1.7:5555`. |
| `stationHost` | IP или имя колонки для SSH. |
| `stationPort` | Порт SSH, по умолчанию `2222`. |
| `stationUser` | Пользователь SSH, по умолчанию `root`. |

### Флаги

| Флаг | Назначение |
|---|---|
| `-config` | Путь к JSON-конфигу. |
| `-address` | Адрес HTTP-сервера. |
| `-music-root` | Корень музыкальной библиотеки. |
| `-cache-dir` | Каталог кэша перекодированных MP3. |
| `-upload-dir` | Каталог загрузок. |
| `-public-base` | Внешний адрес, доступный колонке. |
| `-station-mode` | `adb` или `ssh`. |
| `-station-serial` | ADB-serial. |
| `-station-host` | Хост для SSH. |
| `-station-port` | Порт SSH. |
| `-station-user` | Пользователь SSH. |

### Переменные окружения

Поддерживаются:

```text
MUSIC_WEB_ADDRESS / ADDRESS
MUSIC_ROOT
MUSIC_CACHE_DIR
MUSIC_UPLOAD_DIR
MUSIC_PUBLIC / PUBLIC_BASE
STATION_MODE
STATION_SERIAL
STATION_HOST
STATION_PORT
STATION_USER
FFMPEG_PATH
FFPROBE_PATH
```

Приоритет: явные флаги и переменные окружения переопределяют файл конфигурации. Переменные окружения применяются после флагов.

## Режимы подключения к колонке

### ADB — рекомендуемый для проверенной конфигурации

```sh
adb connect 192.168.1.7:5555
```

Значения:

```text
stationMode=adb
stationSerial=192.168.1.7:5555
```

Режим ADB был проверен на реальной Станции Лайт.

### SSH

Значения:

```text
stationMode=ssh
stationHost=192.168.1.7
stationPort=2222
stationUser=root
```

Приложение вызывает `ssh` с `BatchMode=yes`, поэтому SSH должен быть настроен для неинтерактивного входа, например по ключу без пароля. Интерактивный ввод пароля в текущей реализации не поддерживается. Для этой задачи рабочим и протестированным вариантом является ADB.

## Веб-интерфейс

### Музыка по ссылке

Раздел «Музыка по ссылке» находится рядом с библиотекой.

1. Вставьте прямую HTTP/HTTPS-ссылку на аудиофайл или поток.
2. При желании укажите понятное название — оно будет показано в очереди.
3. Для радио или другого непрерывного потока отметьте «Прямой эфир / радио».
4. Нажмите «Добавить ссылку в очередь».

Примеры подходящих ссылок:

- прямой аудиофайл: `https://example.com/music/track.flac`;
- поток радио: `https://example.com/radio/stream.aac`.

Неподходящие ссылки:
- обычные веб-страницы с плеером;
- страницы авторизации или страницы, где аудио доступно только после входа;
- ссылки с уже истёкшей подписью или токеном.

Конечный удалённый файл проверяется через `ffprobe` и транскодируется так же, как локальный файл. При успешном первом воспроизведении он кэшируется на диске компьютера. Для него поддерживаются длительность, очередь и перемотка.

Для режима «Прямой эфир» метаданные не проверяются заранее: трек появляется в очереди сразу. `ffmpeg` получает данные из источника, транскодирует их в MP3 и передаёт колонке через компьютер. Такой трек:

- не кэшируется на диске;
- не имеет длительности — в очереди отображается «Эфир»;
- не поддерживает перемотку;
- играет до остановки, переключения на другой трек или завершения потока.

Подключение эфира может занять несколько секунд: приложению нужно получить и транскодировать первые данные, а Станции — открыть локальный поток и подготовить ALSA. В это время интерфейс показывает «Подключаем эфир…» вместо тревожного статуса «Звук не подтверждён». Если статус сохраняется долго, проверьте источник, громкость и техническую диагностику в настройках.

Если обычная ссылка указывает на аудио, но `ffprobe` не может определить её длительность, приложение может автоматически пометить трек как прямой эфир — при условии, что удалённый источник действительно содержит аудиопоток. Это полезно для радио-потоков без чёткой длительности.

Компьютер остаётся релеем: Станция обращается только к приложению, а приложение — к внешнему источнику. Если внешняя ссылка станет недоступной, воспроизведение остановится с ошибкой.

### Библиотека

- Нажмите на название папки, чтобы открыть её. Путь над списком позволяет вернуться к любой родительской папке.
- Поле поиска фильтрует содержимое текущей папки по названию.
- «+ Добавить» рядом с файлом, папкой или M3U-плейлистом добавляет его в очередь.
- Для нескольких элементов отметьте флажки и нажмите «Добавить выбранное (N)». «Выбрать всё» отмечает только элементы, видимые с текущим поиском; уже выбранные скрытые элементы остаются выбранными и учитываются в N.
- «Добавить всю папку» добавляет всю текущую папку независимо от поиска. Флажок «Включать вложенные папки» управляет обходом подпапок.
- «Загрузить файлы» отправляет аудиофайлы с устройства, на котором открыт браузер, в библиотеку и очередь.
- «Загрузить папку» сохраняет структуру выбранной папки. Из неё передаются только поддерживаемые аудиофайлы.

При добавлении сразу появляется сообщение о подготовке музыки, повторные нажатия блокируются. При загрузке с устройства показывается процент передачи, затем — обработка метаданных. После ответа сервера очередь появляется сразу, без ожидания отдельной проверки Станции. Добавление или загрузка музыки останавливает текущее воспроизведение; после этого нажмите «Слушать».

Сервер читает метаданные максимум четырьмя процессами `ffprobe` одновременно, в том числе при нескольких запросах. Названия и длительность локальных файлов кэшируются в памяти (до 4096 записей, с очисткой завершённых записей при достижении лимита). Изменение размера или времени модификации файла вызывает повторное чтение. Ошибки не кэшируются, метаданные HTTP-источников проверяются каждый раз. После перезапуска кэш заполняется заново. Треки папок сортируются по имени с учётом чисел (`2` перед `10`); порядок M3U и выбранных элементов сохраняется.

Загрузка папок использует браузерный механизм `webkitdirectory`. Флажок «Также добавить в очередь» позволяет сохранить файлы только в библиотеку. Передачу можно отменить; уже сохранённые файлы остаются. При совпадении имён сохраняются оба файла: новый получает суффикс ` (1)`, ` (2)` и т. д. Файл публикуется целиком после записи во временный файл; существующий файл не перезаписывается. В результатах видны сохранённые, переименованные и пропущенные файлы.

### Плеер и очередь

Плеер закреплён внизу окна и остаётся доступным при прокрутке. На широком экране библиотека и очередь стоят рядом; на телефоне между ними можно переключаться кнопками «Библиотека» и «Очередь». Ссылка, загрузка и настройки открываются в отдельных окнах. Кнопки плеера:

- «Слушать» — воспроизвести с текущего или первого трека;
- «Стоп» — остановить;
- «Следующий» и «Предыдущий» — переключить трек;
- ▶ рядом с треком в очереди — начать с этого трека;
- «Очистить» в заголовке очереди — после подтверждения остановить воспроизведение и убрать все треки.

Текущий трек выделен в очереди. Рядом с количеством треков указана общая длительность. Очередь поддерживает до 1000 треков; сообщение после добавления показывает число принятых треков и сообщает о достижении лимита. Громкость управляется ползунком в плеере; на телефоне он раскрывается через «Громкость и состояние». Добавление музыки сохраняет текущую сессию и порядок уже добавленных треков. Во время чтения метаданных доступны Stop и громкость. Стрелки ↑/↓ меняют порядок очереди, × удаляет отдельный трек. Удаление текущего трека требует подтверждения и останавливает его. Нажмите название или кнопку ••• в плеере, чтобы открыть полные сведения и скопировать путь/ссылку.

### Настройки

Окно настроек открывается кнопкой «Настройки» в шапке. Здесь можно изменить каталог музыки, адрес сервера для колонки, режим подключения и параметры ADB или SSH. Отображаются поля выбранного способа подключения.

Перед сохранением изменений приложение объясняет последствия и запрашивает подтверждение. Изменения сохраняются в файл конфигурации и останавливают воспроизведение. Сохранение тех же значений не отправляет команд колонке. Смена корня библиотеки очищает очередь. Адрес потока, цель подключения и состояние ALSA находятся во вложенном разделе «Техническая диагностика».

## Форматы и плейлисты

Поддерживаемые аудиофайлы:

```text
.aac
.flac
.m4a
.mp3
.oga
.ogg
.opus
.wav
.wma
```

Поддерживаемые плейлисты:

```text
.m3u
.m3u8
```

Правила:

- относительные пути в M3U интерпретируются относительно файла плейлиста;
- HTTP/HTTPS-ссылки поддерживаются, если их может обработать `ffmpeg`; для ссылок без включённого режима «Прямой эфир» также должен успешно работать `ffprobe`;
- для M3U можно использовать `#EXTINF:` как название удалённого трека;
- признак «Прямой эфир» для M3U определяется по результату проверки аудиопотока, а не только по нулевой длительности в `#EXTINF`;
- абсолютные локальные пути отклоняются;
- символические ссылки, выходящие за пределы библиотеки, отклоняются;
- неподдерживаемые или повреждённые файлы пропускаются и отображаются как пропущенные.

## Кэш

Перекодированные MP3 сохраняются в `cacheDir`.

Особенности:

- кэш не очищается автоматически;
- повторное воспроизведение того же файла использует готовый MP3;
- идентификатор кэша учитывает путь, размер и время изменения исходника;
- идентификатор кэша удалённого конечного файла основан на его ссылке; удалённый источник может изменить содержимое без смены ссылки, и тогда старый кэш будет использован повторно;
- при изменении файла он перекодируется заново;
- треки с признаком «Прямой эфир» не пишутся в кэш и не занимают место на диске;
- кэш можно безопасно удалить, пока приложение остановлено.

## HTTP API

Основные эндпоинты:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/config` | Получить текущую конфигурацию. |
| `POST` | `/api/config` | Изменить конфигурацию. |
| `GET` | `/api/library?path=.` | Получить содержимое каталога. |
| `POST` | `/api/library/open` | Разобрать файл, папку или плейлист без изменения очереди. |
| `POST` | `/api/upload` | Загрузить файлы. Multipart-форма. |
| `GET` | `/api/queue` | Получить очередь. |
| `POST` | `/api/queue` | Создать, дополнить или отредактировать очередь. |
| `DELETE` | `/api/queue` | Остановить воспроизведение и очистить очередь. |
| `GET` | `/api/status` | Получить очередь, статус воспроизведения и параметры подключения. |
| `POST` | `/api/control` | Управление: `play`, `index`, `next`, `prev`, `stop`. |
| `GET` | `/api/volume` | Прочитать громкость Станции. |
| `POST` | `/api/volume` | Установить громкость Станции. |
| `GET` | `/music/q/{queue}/{track}.mp3` | Внутренний поток для колонки. |

Пример добавления прямой ссылки:

```sh
curl -X POST http://127.0.0.1:8080/api/queue \
  -H 'Content-Type: application/json' \
  -d '{"action":"append","url":"https://example.com/stream","title":"Моё радио","live":true}'
```

Поля запроса:

- `url` — одна прямая HTTP/HTTPS-ссылка; нельзя передавать одновременно `url` и `paths`;
- `title` — необязательное название;
- `live` — `true` для радио и непрерывного потока;
- `action: "append"` — добавить к текущей очереди.

Для перестановки и удаления передайте `action: "move"` / `"remove"`, `queueId`, актуальную `version` и `entryId` из ответа очереди. Для `move` нужен `toIndex` (с нуля). Если версия устарела, сервер вернёт HTTP 409; получите очередь заново и повторите действие. `entryId` различает даже два вхождения одного файла. `POST /api/control` с `action: "index"` также принимает `entryId`, чтобы запустить нужное вхождение после перестановки.

Пример управления:

```sh
curl -X POST http://127.0.0.1:8080/api/control \
  -H 'Content-Type: application/json' \
  -d '{"action":"stop"}'
```

Пример просмотра статуса:

```sh
curl -fsS http://127.0.0.1:8080/api/status | jq .
```

Пример изменения громкости:

```sh
curl -X POST http://127.0.0.1:8080/api/volume \
  -H 'Content-Type: application/json' \
  -d '{"percent":40}'
```

## Диагностика

### Колонка не начинает воспроизведение

1. Проверьте ADB:

   ```sh
   adb devices
   ```

2. Проверьте, что `publicBase` использует IP компьютера, доступный колонке:

   ```text
   http://192.168.1.9:8080
   ```

   Адрес `127.0.0.1` для колонки не подходит.

3. Убедитесь, что порт открыт для локальной сети:

   ```sh
   curl -I http://192.168.1.9:8080/
   ```

4. Посмотрите статус:

   ```sh
   curl -fsS http://127.0.0.1:8080/api/status | jq .
   ```

5. Убедитесь, что `ffmpeg` и `ffprobe` установлены:

   ```sh
   ffmpeg -version
   ffprobe -version
   ```

### Звук не останавливается

Приложение использует BusyBox-совместимую остановку процесса `maind --gst-launch`. Команда `pkill` на колонке отсутствует, поэтому она не применяется.

Сначала приложение отправляет `SIGINT`, ждёт завершения и при необходимости применяет `SIGKILL`. После завершения оно удаляет оставшиеся общие буферы и семафор ALSA `dmix`, только если буферы созданы остановленным процессом и больше никем не используются. Это предотвращает зависание следующего запуска в `PREPARED` после ручной остановки или переключения. Ключи IPC берутся из `/etc/asound.conf`; файл не изменяется.

Если звук продолжает играть, проверьте процесс на колонке:

```sh
adb -s 192.168.1.7:5555 shell 'ps | grep "[m]aind.*gst-launch" || true'
```

Перед выполнением команд на колонке сверьтесь с применимыми разделами локальной вики, как требует `AGENTS.md`.

### Интерфейс пишет «Играет», но звука нет

Сначала посмотрите громкость в статусе:

```sh
curl -fsS http://127.0.0.1:8080/api/status | jq '.active, .volume'
```

Если `active.playing` и `active.audioAdvancing` равны `true`, а `active.audioState` — `RUNNING`, приложение видит движение аппаратного указателя ALSA. Это подтверждает работу PCM, но не измеряет слышимый звук. Проверьте поле `volume.percent`:

- `0%` — звук полностью отключён;
- `1–9%` — громкость может быть почти неслышимой;
- более высокие значения обычно комфортнее.

Громкость можно изменить в веб-интерфейсе или запросом:

```sh
curl -X POST http://127.0.0.1:8080/api/volume \
  -H 'Content-Type: application/json' \
  -d '{"percent":40}'
```

Приложение использует штатный скрипт Станции `/system/vendor/quasar/set_volume.sh`; он эквивалентен `amixer set Master N%`.

### Статус «Нет звука», ALSA остаётся в PREPARED

Поле `active.audioHwPtr`, которое не меняется между проверками, означает, что приложение не подтверждает вывод звука. Посмотрите `active.error` и журнал сервиса:

```sh
journalctl --user -u station-music-web.service -n 100 --no-pager
```

Журнал systemd доступен, если приложение запущено как пользовательский сервис с таким именем. При обычном запуске сообщения выводятся в терминал.

На Станции Лайт воспроизведено зависание после принудительного завершения плеера: общие буферы ALSA `dmix` сохранялись, следующий процесс открывал PCM, но аппаратный указатель оставался на нуле. Очистка неиспользуемых буферов восстановила воспроизведение без перезагрузки. Приложение выполняет такую очистку при остановке своего плеера с проверками владельца и числа подключений.

До обнаружения этой причины помогала перезагрузка колонки; перезапуска quasar было недостаточно. Это результат диагностики конкретного устройства, а не универсальный рецепт из вики: такой случай в ней не описан. Приложение не перезагружает колонку автоматически и не удаляет буферы, используемые другими процессами.

## Что приложение делает и не делает на Станции

Приложение:

- запускает `./maind --gst-launch ...`;
- завершает предыдущий процесс перед переключением или остановкой;
- очищает оставшиеся неиспользуемые объекты IPC `dmix`, созданные этим процессом.

Приложение не:

- устанавливает пакеты;
- редактирует конфигурацию прошивки;
- изменяет автозапуск;
- монтирует каталоги компьютера;
- делает постоянных изменений на Станции.

## Безопасность

- Веб-интерфейс и API не имеют аутентификации.
- Любой пользователь локальной сети, которому доступен порт, может:
  - видеть имена файлов;
  - увидеть прямую ссылку в очереди;
  - изменять настройки;
  - загружать файлы;
  - запускать воспроизведение.
- Приложение может обращаться к внешним HTTP/HTTPS-источникам, указанным пользователем. Не добавляйте ссылки, ведущие к приватным сервисам или ресурсам с чувствительными данными.
- Подписанные ссылки и ссылки с токеном могут перестать работать после истечения их срока.
- URL потока содержит случайный токен, но это не замена аутентификации API.
- Токен меняется при перезапуске приложения.
- Порт `8080`, ADB `5555` и SSH `2222` нельзя открывать в интернет.
- Используйте приложение только в доверенной локальной сети.

Если сервер слушает только `127.0.0.1`, колонка не сможет подключиться к потоку. Для работы колонки нужен адрес компьютера в локальной сети.

## Тесты

```sh
go test -race ./...
go vet ./...
go build -o stationmusic .
```

Дополнительно можно проверить JavaScript:

```sh
node --check static/app.js
```

Для проверки интерфейса в браузере нужны Python с пакетом `playwright` и установленный Chromium:

```sh
python3 testdata/ui_smoke.py
```

Если Chromium не находится в `PATH`, укажите путь через `CHROMIUM_PATH`:

```sh
CHROMIUM_PATH=/path/to/chromium python3 testdata/ui_smoke.py
```

Скрипт запускает локальный сервер статических файлов и подменяет все запросы API. Он не подключается к Станции. Проверяются поиск, выбор и добавление треков, добавление прямой ссылки с режимом прямого эфира, загрузка файлов, кнопки плеера, обработка ошибок, защита от устаревших ответов, перестановка и удаление треков, подтверждения, восстановление фокуса, отмена загрузки, а также экраны шириной 320, 390, 768, 1440 и 1920 пикселей с обычными и длинными данными. Измеряется геометрия и доступность действий; создание скриншотов не означает их визуальную инспекцию. Скриншоты сохраняются во временный каталог, путь к которому выводится в результате проверки. Эти зависимости нужны только для браузерного теста.

Тесты покрывают:

- защиту путей;
- проверку и нормализацию HTTP/HTTPS-ссылок;
- разбор M3U/M3U8;
- чтение метаданных удалённого файла и определение потока без длительности;
- транскодирование и HTTP-ответ для прямого эфира;
- ограничение параллельных проверок, порядок треков, повторное использование и обновление метаданных;
- HTTP Range;
- построение ADB/SSH-команд;
- размер слота очереди;
- чтение потока во время перекодирования;
- BusyBox-совместимую команду остановки.

Перечень ниже относится к предыдущей версии. Обновлённый интерфейс проверен изолированно с подменой API; новая реальная проверка звука не проводилась. При обычном запуске статические файлы встроены в Go-бинарник: после изменений требуются пересборка и перезапуск. Перезапуск останавливает воспроизведение и сбрасывает очередь в памяти.
